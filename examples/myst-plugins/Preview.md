# Project-defined MyST plugins

Open this document in VS Code's built-in Markdown Preview. This folder enables
Markdown Chroma's project plugin setting. If VS Code asks, trust this example
folder to allow the local JavaScript plugin to run.

The sections below are generated by the official MyST documentation plugin
registered in `myst.yml`. They are not written out in this Markdown source.

## Generated directive documentation

:::{myst:directive} code
:::

The custom role links to the generated {myst:directive}`code` documentation and
its {myst:directive}`code.linenos` option.

## Generated role documentation

:::{myst:role} keyboard
:::

The custom role links to the generated {myst:role}`keyboard` documentation.

## Ordinary Markdown and bundled MyST

Ordinary **Markdown** still renders alongside plugin output.

:::{note}
This admonition is provided by the bundled MyST parser.
:::

```python
def greeting(name):
    return f"Hello, {name}!"
```

To compare the behavior, turn off **Markdown Chroma: Preview: Project Plugins**
in this folder's settings. The custom directives become unsupported, while the
ordinary Markdown, admonition, and code block continue to render.
